## Things that are easy to get wrong here

- **Write each gate's test first, and watch it fail** on the current code before changing it.
- **Planned test corrections are not weakened tests.** `PLAN-v1.6.md` §4 lists the only earlier
  tests that change. Correct them, name the gate and D-entry, and list them under "Tests
  corrected" in the report. Nothing else is weakened, skipped or deleted.
- **Expand-only migrations** (SPEC B6). `tasks/0005_references.sql`, `tasks/0006_yearly.sql` and
  `questions/0001_questions.sql` are new and add-only, and are never edited after pushing. Prove
  each new piece of stored data survives a rollback to **v1.5.0** and an upgrade again, in the
  container test.
- **"Today" is always `app.Today`,** never the wall clock. Yearly jobs and holidays depend on it.
- **A waiting yearly job must never leak** into the Board, My jobs, Up for grabs, Team or the
  Briefing, or disturb the To do order. P8-06's every-list and move-order tests exist for this.
- **Holiday dates come from SPEC B14.5's table and the official lists**, never from memory.
- **Sections stay independent** (SPEC B2): Tasks and the Knowledge Base meet only through the
  interfaces wired in `cmd/comphq`, and Questions depends only on `people`, `db` and `app`.
- **Gate 4.11 stays at four icon-only buttons.** Everything new is worded, except that removing an
  article, place or answer uses the existing **remove** icon.
- **Every page works without JavaScript**, and every drag has a button (A2, `PLAN.md` §2.8).
- **MC HQ is the same app.** Run the final screen sweep with `COMPHQ_BRAND=mc` too (P8-13).
- **Pushes and CI:**
  - Never push a `[skip ci]` commit together with code.
  - Never push while the previous push's CI is still running. You may work on the next task
    locally meanwhile.
  - CI takes 15–25 minutes a push.
- **This machine:**
  - You can't take screen pictures or open a visible browser. Use Playwright screenshots and read
    them with the file-reading tool.
  - `SPEC.md` uses CRLF line endings. Keep each file's own line endings.
  - Write TypeScript and regex-heavy files with the file-writing tool, not shell heredocs.
